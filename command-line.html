onetime
How it works

Use onetime from the command line

onetime is also a single-file command-line tool. It uses the same encryption and the same links as this site: a link made on the command line opens in a browser, and the other way round. The server never sees the secret or the key.

It has been run on Linux. Windows and macOS are not tested yet.

Install

One file. It needs only Node.js 22 or newer.

Linux and macOS

curl -fsSL https://onetimepass.pages.dev/cli/onetime.mjs -o onetime && chmod +x onetime

Or save the file as onetime.mjs and run it as node onetime.mjs.

Windows

Download onetime.mjs and onetime.cmd into a folder that is on your PATH. Then run it as onetime.

Check the download

A SHA-256 checksum is at /cli/onetime.mjs.sha256. Compare it with the output of sha256sum onetime (macOS: shasum -a 256 onetime). It comes from the same site, so it detects a damaged download, not a compromised server.

Commands

onetime send
Reads the secret from a pipe or a hidden prompt, encrypts it and prints only the link. With --passphrase it also asks for a passphrase, twice; --passphrase-file PATH reads it from the first line of a file instead.
onetime send --file PATH
Encrypts one file of up to 256 KB, its name included, and prints only the link. --name NAME sets the name the recipient sees; --file - reads the file from a pipe. A file link lasts 1 hour. The tool asks the server for its limits first; a self-hosted server may set another file size, up to 5 MB, and a longer file life.
onetime gen
Generates a password or token and creates the link in one step. With --print-only it only prints a generated secret and contacts no server.
onetime get -
Asks you to paste the link, reveals the secret and uses the link up. If the link needs a passphrase, it asks for it (or reads --passphrase-file PATH); a wrong one destroys the secret. A file is saved with -o PATH, or written to the output when you redirect it.
onetime status -
Checks whether the link is still waiting, without using it up.

Run onetime --help or onetime gen --help for all options.

The current version is 0.5.0. Links made since 20 November 2026 need at least 0.3.0; older versions report them as damaged without using them up. onetime --version shows your version.

Examples

On Windows, write onetime instead of ./onetime.

Share a secret

Type it at the hidden prompt, or pipe it in from a file. The link expires after 1 hour here.

./onetime send --ttl 1h
./onetime send --ttl 1h < secret.txt

Protect it with a passphrase

--passphrase asks at a hidden prompt, so it needs a terminal. With a piped secret, put the passphrase in a file. Send the passphrase to the recipient another way than the link. 

./onetime send --passphrase
./onetime send --passphrase-file passphrase.txt < secret.txt

Send a file

Up to 256 KB, or the limit of the server you send to. The name and contents are encrypted on your computer.

./onetime send --file report.pdf --ttl 1h
tar czf - notes | ./onetime send --file - --name notes.tar.gz

Generate a password and share it

./onetime gen --type password --length 32

Open a link

Paste the link when asked. This uses the link up, like the Reveal button.

./onetime get -

Save a file

Give a folder or a new file name with -o. An existing file is never overwritten, and the target is checked before the link is used up. Without -o, redirect the output; on a terminal nothing is opened. 

./onetime get - -o ~/Downloads/
./onetime get - > report.pdf

Check a link without opening it

./onetime status -

Exit codes

  • 0 done.
  • 1 the link is gone: already opened or expired.
  • 2 usage error, also a missing passphrase, a target file that already exists, or a file link on a terminal without -o. Nothing is opened.
  • 3 damaged or incomplete link. Nothing is opened.
  • 4 decryption failed, also after a wrong passphrase. The link is used up.
  • 5 network or server error, or the file could not be written after it was opened.
  • 70 internal error.

Privacy

  • The secret is never taken as a command-line argument, so it stays out of shell history and process lists.
  • A link passed as an argument to get does end up in shell history. Use onetime get - or open the link in a browser instead.
  • No telemetry, no config files, no update checks.
  • Since 0.5.0, send and get tell the server the kind of link (text or file, passphrase or not). The hosted service adds it to daily totals (see privacy); it is never stored with the secret.

How your secret is stored explains the encryption and what the server keeps. It is the same for the command line.

Share a secret in the browser

No accounts. Secrets are encrypted on your device. No page of this site sets cookies or loads anything from other sites; it keeps only daily totals without identifiers. Your theme choice is saved in your browser.
